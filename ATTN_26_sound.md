### Расхождения документов с кодом (правятся вместе с этим разделом)

2. `dcc_on_dc_buzz` (ATTN_21 §21.5) существует только в документе: DCC в коде нет.
3. TDD §8.3.3 отмечает стыки `[x]` как «вибрация и звук». Вибрация есть, звука нет, только событие.
4. TDD §8.3.4 обещает «лязг по цепочке» при старте локо. Событие `on_coupler_force` есть, звука нет.
5. ATTN_16 §16.2 пишет, что у `GFX.time_of_day_changed` подписчиков нет. Это устарело: подписан `C_Mechanisms` (правило света `NIGHT`, шаг L3). Звук на сигнал не подписан. Строка в ATTN_16 §16.2 исправлена.

## 26.2. Принципы (из архитектуры проекта)

- **Звук это компонент, а не система.** TDD §2: логика внутри компонентов, шина событий, никаких `Systems`. Компонент `C_Sound` реагирует на события своей сущности методами `on_*`, как `C_Mechanisms`. Чужие файлы для добавления звука не правятся.
- **Один компонент на сущность** (Entity не допускает два компонента одного типа). `C_Sound` держит список голосов и привязок внутри, как `C_Mechanisms` держит `Mech` и `Lamp`.
- **Владение нодами.** `AudioStreamPlayer3D` создаёт и держит `C_Sound`. Другие компоненты к ним не обращаются, только событиями.
- **Данные отдельно от исполнения.** Что и когда играть, лежит в ресурсах (`SoundProfile`), как `LightConfig` и `MechanismConfig`. Новый звук это строка в данных.
- **Глобальное через автолоад.** Всё, что приходит мимо `Entity` (сигналы `PGM` и `GFX`, интерфейс, музыка, шины), обслуживает автолоад `SND` по образцу `PGM`, `GFX`, `TGM`.
- **Ни одной строки звука внутри DCS, физики и UI-логики.** Они сообщают состояние, звук подписывается (ATTN_10 §10.11).
- **Бюджет первичен.** Лимит одновременных голосов, отсечение по расстоянию до камеры, редкие события (стыки 500 траков, много вагонов) идут с cooldown и приоритетом.
- **Режим управления подчиняет звук.** Debug, Упрощённое, Реалистичное (ATTN_16 §16.11): что игрок может включить сам, а что включает автоматика, решает тот же `ControlMode`.
- **Звук локо зависит от питания** как свет по L8a: нет напряжения под тележками, нет двигателя.

## 26.3. Архитектура

```
project.godot            [audio] driver: убрать Dummy (headless-запуск и так использует Dummy, проверить)
default_bus_layout.tres  Master
                         ├─ World ── Engine, Mechanics, Electric
                         ├─ UI
                         ├─ Music
                         └─ Ambience

SND (autoload, core/audio/sound_manager.gd)
├─ пул голосов, лимит, приоритеты, cooldown
├─ ui(id), world_at(cue, позиция), music(контекст)
├─ мосты к PGM.output_event, PGM.bus_event, GFX.time_of_day_changed
└─ громкости шин из Settings [audio], реакция на паузу и ControlMode

Entity
├─ C_Identity (object_config -> ... sound_profile: SoundProfile)
├─ ... компоненты объекта ...
└─ C_Sound            # on_rail_joint, on_coupled, on_switch_changed, ... -> SoundBinding -> SoundCue
```

**Данные** (ресурсы в `setting/`, по образцу `light_config.gd`):

| Ресурс | Поля |
|---|---|
| `SoundCue` | `id`, источник (`AudioStream`), шина, `volume_db`, разброс `pitch` и громкости, `unit_size` и `max_distance`, `cooldown`, `max_voices`, `loop` |
| `SoundBinding` | `event` (имя события), `cue`, множитель от поля события (`strength`, `v_close`, `force`), условие (например `reason == "tight_curve"`) |
| `SoundLayer` | непрерывный слой (двигатель, гул): `cue`, источник параметра (`SPEED`, `VOLTAGE`, `FORCE`), кривая громкости и тона |
| `SoundProfile` | первый шаг: один плоский ресурс с файлами и уровнями (§26.3.1); позже списки `bindings` и `layers` и карта функций декодера (§26.5.3) |

Где лежит ссылка на профиль: на первом шаге поле в `WagonConfig` (локо и вагоны), для стрелок и пультов позже базовый класс или поле в `ObjectConfig` (Q1).

### 26.3.1. `SoundProfile` первого шага

Один ресурс `setting/sound_profile.gd` без `SoundCue`, `SoundBinding` и `SoundLayer`: поля прямо называют звук. Профиль **не ссылается на файлы**, а хранит их имена без расширения: `SND.load_stream(folder, имя, петля)` ищет `<folder>/<имя>.wav`, `.ogg`, `.mp3`. Поэтому репозиторий собирается без звука (аудио не коммитится), а положенный в `data/sounds/` файл с нужным именем подхватывается при следующем запуске без правки ресурсов. Файла нет: этот звук молчит, ошибок нет.

| Поле | Что это |
|---|---|
| `folder` | папка со звуками, по умолчанию `res://data/sounds` |
| `roll_loop`, `joint_clicks[]` | имена файлов качения и стыков (§26.6.1) |
| `motor_idle_loops[]`, `motor_loop`, `motor_roll_loop` | имена файлов моторчика: варианты холостого хода, обороты без рельсов, обороты вместе с рельсами (§26.5.1); поля двигателя декодера добавятся в S1.4 |
| `motor_gain_db`, `motor_ref_ratio`, `motor_pitch_min`, `motor_pitch_max`, `motor_idle_fade_ratio` | уровень, доля предела оборотов, на которой записана петля (тон 1.0), пределы тона, где холостой ход переходит в обороты |
| `roll_gain_db`, `joint_gain_db` | уровни; у вагона `roll_gain_db` ниже, чем у локо (`SoundProfile.make_default(is_loco)`: 0 и −6 дБ) |
| `roll_ref_speed`, `roll_min_speed`, `roll_pitch_min`, `roll_pitch_max` | скорость, на которой петля качения звучит с тоном 1.0; порог остановки; пределы тона |
| `joint_ref_strength`, `joint_cooldown` | сила стыка для уровня `joint_gain_db`; пауза между стыками одной сущности |
| `unit_size`, `max_distance` | параметры `AudioStreamPlayer3D`; `max_distance` же задаёт радиус, в котором `SND` считает сущность слышимой |

Поле `WagonConfig.sound_profile` пусто у всех объектов: действует профиль по умолчанию. Нужен свой профиль (другая скорость, свои имена файлов): создать ресурс `SoundProfile` и назначить в паспорте вагона. Новый звук позже это новое поле или строка в `bindings`, код цикла не меняется. Петли включаются в коде (`SND.apply_loop`), а не настройками импорта, чтобы файлы не зависели от `.import` (**проверить в редакторе**, особенно при `compress/mode=2` у WAV: поддерживается ли зацикливание в этом режиме сжатия).

## 26.5. Звук локомотива: DC сейчас, DCC потом

Исходим из того, что работает: DC-система (ATTN_10, напряжение на рельсах, мотор по напряжению). DCC ([ATTN_21](0_ATTN_21_dcc.md)) в коде не начата и остаётся перспективой: под неё в §26.5.3 только заложено место.

**Что слышно** (таблица ATTN_21 §21.4, колонка DC):

| Локо | В DC-цепи (первый шаг) | В DCC-цепи (потом) |
|---|---|---|
| без декодера | моторчик и качение; больше ничего | гудит и греется (`dcc_on_dc_buzz`) |
| с декодером | моторчик, качение и звук двигателя декодера по напряжению; функций (гудок, свет, радио) нет | полный профиль по адресу, функции F0–F28 |

Принципы:

1. `C_Sound` слушает события своей сущности и читает состояние шасси и мотора (§26.2). Чужие файлы для звука не правятся.
2. Что откуда берётся: моторчик из оборотов вала `get_motor_speed()` и силы мотора; качение из `current_speed`; стыки из `on_rail_joint`; двигатель декодера из напряжения `C_Engine.power.voltage`.
3. Нет напряжения: нет моторчика и двигателя. Качение остаётся, пока вагон катится по инерции.

### 26.5.1. Моторчик локомотива (электромотор модели)

Моторчик слышен у любого локо, у аналогового локо без декодера это единственный собственный звук. Что отдаёт код (`C_Engine`, `C_Chassis`):

| Величина | Откуда | Что даёт звуку |
|---|---|---|
| `power.voltage` (−100…100 %) | `C_Engine`, `C_Bogie.best_supply` | питание есть или нет; знак это направление |
| `start_voltage` (по умолчанию 6 %) | `WagonConfig` | ниже порога `powered = true`, сила 0, ток `motor_current_idle`: мотор «гудит, но не едет» |
| `force`, `target_speed`, `motor_k` | событие `on_force_changed {force, powered, active, target_speed, motor_k}` | нагрузка: разгон, затор, торможение мотором |
| `chassis.get_motor_speed()` | `C_Chassis`: скорость колёс при пробуксовке, иначе `current_speed` | обороты вала: основа высоты тона |
| `is_slipping` | `C_Chassis` | пробуксовка: обороты растут без движения |

`on_force_changed` уходит в каждом физическом кадре, а не только при изменении: `C_Sound` сам сравнивает с прошлым значением и не перезапускает звук.

**Файлы моторчика** (имена по умолчанию в `SoundProfile`, §26.6.1): `motor_idle_loop_01…03` это варианты холостого хода (питание есть, локо стоит); `motor_only_loop` это мотор на оборотах без рельсов; `motor_roll_loop` это мотор на оборотах вместе со звуком рельсов; `roll_loop` это рельсы без мотора.

**Модель первого шага (сделано в S1.3).** `C_Sound` у сущности с `C_Engine`:

1. Обороты вала `r = |get_motor_speed()| / max_theoretical_speed`: тон идёт за ними, а не за напряжением (у мотора есть инерция и противоЭДС, при том же напряжении разгон и установившийся ход звучат по-разному). Пробуксовка поднимает `r` и тон.
2. Две петли с кроссфейдом равной мощности (`cos` и `sin`): на `r` около 0 звучит холостой ход, выше `motor_idle_fade_ratio` (0.15) звучит петля оборотов с тоном `r / motor_ref_ratio` (пределы 0.5…1.6). При каждом новом включении холостого хода берётся случайный из трёх вариантов.
3. Играет, пока `on_force_changed.powered` и сущность на рельсах; без питания или после схода тишина (плавный спад).
4. Петля оборотов: `motor_only_loop`, а при его отсутствии `motor_roll_loop`. Во втором случае рельсы уже записаны в петле, поэтому отдельное качение (`roll_loop`) у этого локо не добавляется; у вагонов оно играет как обычно. Какой вариант лучше (мотор и рельсы раздельно или записаны вместе), решается слухом: убрать лишний файл из `data/sounds/` достаточно, настраивать ничего не нужно.
5. Нет холостых вариантов: на стоянке играет петля оборотов на низком тоне; нет петли оборотов: всегда холостой ход.
6. Рост (этап 2): несколько петель оборотов по ступеням с кроссфейдом вместо одной с `pitch_scale` (S2.6); громкость от доли силы (затор, разгон).

### 26.5.2. Декодер в DC-цепи

Декодер ставится на DC-систему и воспроизводит только те звуки, которые доступны ему в DC: **звук двигателя по напряжению**. Функций (гудок, колокол, свет, радио) в DC нет, они появятся с DCC (§26.5.3).

- **Компонент** `C_Decoder` (`core/components/trains/c_decoder.gd`) ставится на локо рядом с `C_Engine`. Флаг в `WagonConfig`: `has_decoder` (временно, ATTN_21 §21.5 заменит его на `drive = DECODER` и `decoder_address`). Физику мотора декодер на DC не меняет: аналоговый режим (ATTN_21 §21.4).
- **Состояния по напряжению** `|U|` = `|C_Engine.power.voltage|` [предложение, пороги подобрать в редакторе]:

| Состояние | Вход | Что играет |
|---|---|---|
| `OFF` | `|U|` ниже порога включения (`on_voltage`, около 3 %) | тишина |
| `STARTING` | `|U|` выше `on_voltage` | `engine_start` целиком (или сразу `RUNNING`, если файла нет) |
| `RUNNING` | после `STARTING` | петли `engine_idle_loop` и `engine_run_loop`: громкость и тон от `|U|` (с одним файлом только тон) |
| `STOPPING` | `|U|` ниже `off_voltage` дольше `off_delay` (гистерезис, без дребезга) | `engine_stop` целиком, затем `OFF` |

- **Событие** `on_decoder_state {state, level}` (`level` = `|U| / 100`): обычное событие шины, на него подписан `C_Sound`. Так `C_Sound` не знает, откуда пришло напряжение, и при DCC читает те же события.
- Запуск пока не задерживает движение (физику не трогаем); задержка движения до конца запуска это Q6.

### 26.5.3. DCC потом: функции и карта функций

Когда появится DCC: `C_Decoder` получит адрес и функции F0–F28 и будет слать `on_decoder_function {n, on}` (ATTN_21 §21.4). В `SoundProfile` добавится **карта функций**: `функция → cue`, режим (`TOGGLE`, `MOMENTARY`, `TIMED`), группа взаимоисключающих (два гудка). Двигатель при этом идёт за ступенью скорости, остальное включается функциями; раскладка номеров у каждой модели своя (Q2). `ControlMode` (ATTN_16 §16.11): Debug даёт вкладку «Звук» с кнопками функций, «Упрощённое» включает двигатель и сигналы автоматически, «Реалистичное» только через станцию, пульт и клавиши F. На DCC-цепи DC-локо без декодера гудит (`dcc_on_dc_buzz`). Задача после этапа 1 (S2.5).

## 26.6. Минимальный набор звуковых файлов и звук вагонов

### 26.6.1. Минимальный набор

Чтобы запустить звук движения (локо без декодера, вагоны, декодер в DC), достаточно **четырёх файлов** (строки 1–4). Остальные улучшают звук и добавляются без правки кода.

| № | Файл | Вид | Длина | Для чего | Статус |
|---|---|---|---|---|---|
| 1 | `motor_only_loop` | петля | 5–8 с | моторчик локо на оборотах, без рельсов (§26.5.1) | обязательно |
| 1а | `motor_idle_loop_01`, `_02`, `_03` | петли | 5–8 с | моторчик, холостой ход: варианты, берётся случайный | желательно (без них на стоянке играет `motor_only_loop` на низком тоне) |
| 1б | `motor_roll_loop` | петля | 5–8 с | моторчик на оборотах вместе с рельсами; играет вместо 1 и 2 для локо, если файла 1 нет | запасной |
| 2 | `roll_loop` | петля | 5–8 с | качение колёс: у локо громче, у вагонов тише (§26.6.3) | обязательно |
| 3 | `joint_click_01` | одиночный | 0.08–0.25 с | стык рельс, событие `on_rail_joint` | обязательно |
| 4 | `engine_idle_loop` | петля | 6–10 с | двигатель декодера в DC (§26.5.2) | обязательно для декодера |
| 5 | `joint_click_02`, `joint_click_03` | одиночные | 0.08–0.25 с | варианты стыка, чтобы удары не повторялись один в один | желательно |
| 6 | `engine_run_loop` | петля | 6–10 с | двигатель под нагрузкой; с ним `idle` и `run` смешиваются по напряжению, без него один `idle` меняет тон | желательно |
| 7 | `engine_start`, `engine_stop` | одиночные | 2–8 с | запуск при подаче напряжения и остановка при снятии | желательно |

Файлы кладутся в `data/sounds/` под именами из таблицы (расширение `.wav`, `.ogg` или `.mp3`); больше ничего настраивать не нужно, профиль находит их по имени. Тип локо для первых звуков решает автор (Q5): для дизеля файлы 4, 6, 7 это дизель, для электровоза это гул и компрессор, для паровоза двигатель завязан на вращение колёс и в первый шаг не входит. Файлы одного типа локо должны быть из одной записи или одного «семейства» по уровню и тембру.

### 26.6.2. Желательные характеристики

**Общие для всех файлов:**

| Параметр | Желательно | Почему |
|---|---|---|
| Формат | WAV 16 бит PCM; OGG Vorbis (около q6) годится для выпуска | Godot читает оба; WAV точнее для отладки |
| Каналы | **моно** | `AudioStreamPlayer3D` ставит звук в пространство сам; стерео в 3D не нужно |
| Частота дискретизации | 44100 или 48000 Гц, не ниже | при 22 кГц и ниже верх спектра отсутствует, тон при сдвиге глохнет |
| Уровень | пик −3…−1 dBFS, без клиппинга; уровень петель одного семейства сопоставим | баланс потом задаётся в игре (`*_gain_db`), а не правкой файлов |
| Запись | «сухая»: без реверберации комнаты, музыки и речи, без звука других функций | реверберацию и приглушение даёт игра по расстоянию |
| Шум | ровный и тихий фон; без щелчков тока, шороха, наводок сети | несколько вагонов подряд сложат шум и усилят его |
| Имена | латиница в нижнем регистре, как в таблице; папка `data/sounds/` | совпадают с полями `SoundProfile` |

**Петли (1, 2, 4, 6):**
- Бесшовные: конец переходит в начало без щелчка и скачка громкости. Если запись длиннее, взять ровный кусок и сделать кроссфейд хвоста с головой 0.3–0.5 с; в файле нет затухания в начале и конце.
- Ровный тон и громкость внутри петли (без «плавания» оборотов), без разовых событий (щелчок, гудок, хлопок): иначе повтор слышен.
- Длина 5–8 с и больше: короче слышен повтор.
- Записаны на **средних** оборотах или скорости: игра сдвигает тон вверх и вниз примерно в пределах от 0.6 до 1.6, а крайние значения звучат хуже.
- `motor_only_loop`, `motor_idle_loop_*`: записаны на постоянном напряжении, лучше с локо на роликовом стенде или в руке, без стука колёс о рельсы и без дизеля.
- `roll_loop`: ровное качение с шорохом колёс, без явных отдельных ударов (удары это стыки, файлы 3 и 5).

**Одиночные (3, 5, 7):**
- Звук начинается сразу (тишина в начале не больше 10 мс) и затухает естественно, без обрезанного хвоста.
- Стык 0.08–0.25 с: короткий «тук» колеса на стыке; варианты различаются тембром и уровнем на 1–2 дБ.
- Запуск и остановка: нет посторонних событий внутри (гудка, речи).

**Проверка перед передачей:** послушать петлю в редакторе звука подряд 1–2 минуты, шов не слышен; по спектру нет шумов выше 16 кГц, которые не нужны; пик не выше −1 dBFS. Источник и лицензия каждого файла записываются (`data/sounds/CREDITS.md`, S4.5).

### 26.6.3. Звук вагонов в составе

**Нужен ли.** Да. Вагоны это основная часть состава, и по звуку состав узнаётся по стыкам в такт скорости (код уже шлёт `on_rail_joint` каждой тележки: `kind` `track` или `rail`, сила `joint_kick × min(скорость, joint_speed_cap)`). Без звука вагонов локо едет «один» с моторчиком.

**Будет ли слышен.** Да, ближние вагоны слышны, дальние тонут по расстоянию. Но суммарный звук растёт с числом вагонов (несвязанные источники: примерно +3 дБ на удвоение), поэтому правила такие [предложение, подобрать в редакторе на слух]:

1. **Тише локо.** `roll_gain_db` вагона ниже, чем у локо (начать с −6 дБ); у локо к качению добавляется моторчик (§26.5.1).
2. **Те же файлы.** Вагон использует `roll_loop` и `joint_click_*` (§26.6.1), отдельных файлов не требует; тон и громкость идут за `current_speed` (петля качения `pitch_scale` от `|v| / roll_ref_speed`, громкость растёт со скоростью).
3. **Только движущиеся и ближние.** Петля качения играет, пока `|v|` выше порога (около 0.05 м/с) и вагон ближе `max_distance`; остановившийся вагон замолкает с плавным спадом. Голоса качения ограничены (начать с 12 ближайших к слушателю), остальные молчат.
4. **Не в унисон.** Случайный сдвиг старта петли, тон ±3 %, громкость ±1 дБ у каждого вагона: иначе одинаковые вагоны складываются в «гребёнку» (фазовый звон).
5. **Стыки.** Событие `on_rail_joint` играет один из `joint_click_*`: громкость от `strength`, `cooldown` на сущность (около 40 мс) и общий бюджет стыков в секунду в `SND` (редкие по смыслу, но на составе из 50 вагонов их много).

Если голосов вагонов не хватает (Q7), следующий вариант: один «голос качения» на состав у ближайшей к слушателю точки (центр состава) с громкостью от числа вагонов; решается замером в S1.5.

### Этап 3. Звуки интерфейса (вторично)

**Цель:** отклик интерфейса звуком, настройка громкостей.

**Файлы:** `core/audio/sound_manager.gd` (`ui()`), `ui/windows/settings_window.*` (страница «Звук»), `data/sounds/ui/`.

- [ ] **S3.1 `SND.ui(id)` и автоподключение.** Подписка на `node_added` и подключение `pressed` у `BaseButton`, исключение по метке `no_sound`. Сцены правятся только там, где нужен особый звук.
- [ ] **S3.2 Набор cue.** Клик, переключатель, подтверждение, отмена, ошибка (`LYM.notice`, Hints), открытие и закрытие окна, сохранить и загрузить, Esc из стека (ATTN_17 U10).
- [ ] **S3.3 Страница «Звук» в окне настроек.** Страница и строки `SettingRow` по шинам уже есть (U11, серые). Включить их: убрать заметку, привязать слайдеры к `AudioServer` и `Settings` `[audio]`, добавить mute и «по умолчанию», применение сразу.
- [ ] **S3.4 Отказы.** Звук ошибки дублирует метку: отказ соединения провода (ATTN_10), отказ постановки трака, лимиты. Решает принцип «состояние не только цветом» (ATTN_17 §17.6.7).

**Проверка в редакторе:**

1. Клик по кнопкам верхней панели, боковой панели и системного меню звучит; наведение тихое или молчит.
2. Отказ постановки трака и соединения провода даёт звук ошибки одновременно с подсказкой.
3. Слайдеры «Звук» меняют громкость шин сразу; значения сохраняются в `user://settings.cfg` и переживают перезапуск; «по умолчанию» возвращает 100%.
4. В паузе кнопки меню звучат, а мир молчит.
5. Кнопка с меткой `no_sound` молчит.

### Этап 4. Музыка (третично)

**Цель:** музыка по контексту, окружение комнаты, ритуал первой подачи питания.

**Файлы:** `core/audio/sound_manager.gd` (`music()`), `core/audio/music_player.gd`, `data/sounds/music/`, `data/sounds/ambience/`.

- [ ] **S4.1 `MusicPlayer`.** Плейлисты по контексту (меню, Build, Operate, Observe), кроссфейд, без повтора подряд; контекст приходит от `SceneRouter` (ATTN_19) и `ToolController.set_mode`.
- [ ] **S4.2 Приглушение (ducking).** Музыка тише на гудке и на звуках отказа, возвращается плавно; настройка «музыка в Observe».
- [ ] **S4.3 Окружение комнаты.** Тиканье, далёкие звуки дома, переход день и ночь по `GFX.time_of_day_changed` (ATTN_14 S10), шина `Ambience`.
- [ ] **S4.4 Ритуал первой подачи питания.** Пауза, звук, всплеск света лампы (GDD §10, ATTN_14 S10).
- [ ] **S4.5 Материалы.** Формат OGG, список источников и лицензий в `data/sounds/CREDITS.md`.

**Проверка в редакторе:**

1. При переходе меню → игра → Observe музыка меняется кроссфейдом без щелчков и без повтора трека подряд.
2. Громкость `Music` настраивается отдельно от эффектов и от `Master`.
3. Гудок локо приглушает музыку и возвращает её без рывка.
4. Смена времени суток меняет фон комнаты; тиканье не слышно в меню.
5. Первая подача питания на новом контуре даёт ритуал один раз, повторно не срабатывает.

## 26.8. Решения и открытые вопросы

| # | Вопрос | Решение |
|---|---|---|
| D1 | Звук как компонент или как система | **Компонент** `C_Sound` плюс автолоад `SND` для глобального (TDD §2) |
| D2 | Что звучит у DC-локо | моторчик и качение; декодер в DC добавляет двигатель по напряжению; функций в DC нет (§26.5) |
| D3 | Что слушает слушатель | активная `Camera3D`, в POV фильтр низких частот |
| D4 | Моторчик и двигатель на первом шаге | одна петля с `pitch_scale` и громкостью от параметра; несколько петель с кроссфейдом позже (S2.6) |
| D5 | Данные первого шага | один плоский ресурс `SoundProfile`; `SoundCue`, `SoundBinding`, `SoundLayer` вводятся на этапе 2 (§26.3.1) |
| D6 | Петли и файлы | петли включаются в коде, а не в `.import`; звуковые файлы в репозиторий не коммитятся (решение автора) |
| Q1 | Поле профиля у стрелок и пультов: `ObjectConfig` или базовый класс | **открыто**, для локо и вагонов поле в `WagonConfig` (S1.1) |
| Q2 | Реальные номера F-функций у модели | **открыто**, после DCC (§26.5.3) |
| Q3 | Источник и лицензия каждого звукового файла | **открыто**, до выпуска, записывается в `CREDITS.md` (S4.5) |
| Q4 | Событие `controller_click` и `relay_click`: добавлять в DCS или обходиться меткой от `output_event` | **открыто**, решается в S2.3 |
| Q5 | Тип локо для первых звуков (дизель, электровоз, паровоз) | **открыто**, нужен до передачи файлов 4, 6, 7 из §26.6.1 |
| Q6 | Задерживать ли движение до конца `engine_start`: `powered` в `C_Engine` определяется питанием, значит состояние «двигатель готов» нужно в `C_Decoder`, не меняя электрику | **открыто**, пока не задерживаем (§26.5.2), решается вместе с S2.5 |
| Q7 | Звук вагонов: голос на каждый ближний вагон или один голос на состав | **открыто**, начинаем с голоса на вагон, замер в S1.5 (§26.6.3) |

## 26.9. Риски

| Риск | Решение |
|---|---|
| Много вагонов шлют `on_rail_joint` одновременно | лимит голосов, cooldown, отсечение по расстоянию до камеры в `SND` (S1.2) |
| Качение многих вагонов вместе громкое и «звенит» | вагон тише локо, случайный сдвиг старта, тон ±3 %, лимит голосов (§26.6.3) |
| Петля со сдвигом тона звучит искусственно | запись на средних оборотах, сдвиг около 0.6–1.6, позже несколько петель (S2.6) |
| Шов петли слышен | бесшовная подготовка файла (§26.6.2) и проверка в редакторе звука |
| `node_added` на каждую кнопку интерфейса | подключение лёгкое (одна связь), замерить на тяжёлых панелях; запасной вариант: базовый класс кнопки |
| Звук не совпадает с масштабом стола (1:87) | `unit_size` и `max_distance` подбираются в S1.5 и S2.4 |
| Звук будет конкурировать с тихой «созерцательной» атмосферой Observe | отдельный пресет громкостей для Observe, ducking (S4.2) |
| Недостающие события в DCS | S2.3, правка ATTN_10 |
| Файлов в `data/sounds/` нет или часть пуста | поля `SoundProfile` могут быть пустыми, звук молчит без ошибок (проверка 9 этапа 1) |

## 26.10. Хоткеи

Звук хоткеев не вводит. Функции декодера войдут в раздел хоткеев ATTN_21 §21.6, когда появится DCC.
